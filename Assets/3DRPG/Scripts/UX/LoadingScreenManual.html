ロード画面の仕組み解説

現在のプロジェクトにおけるロード画面（LoadingScreenManager）の仕組みについて、主要なスクリプト（LoadingScreenManager.cs と change_scene_button.cs）の内容をもとに解説します。

全体として「バックグラウンドで次のシーンを読み込みつつ、最低表示時間を設けてTipsを見せる」という、最近のゲームでよく使われる丁寧な作りになっています。

大きく分けて以下の5つの要素で構成されています。

1. シングルトン化とシーン間の維持

LoadingScreenManager はゲーム内に1つだけ存在する「シングルトン（Singleton）」として設計されています。

public static LoadingScreenManager Instance { get; private set; }
// ...
DontDestroyOnLoad(gameObject);

DontDestroyOnLoad を使うことで、シーンが切り替わってもロード画面のUIが破棄されず、画面を跨いでシームレスな表示を維持できるようになっています。

2. 非同期読み込み（バックグラウンドロード）

シーンの読み込みには SceneManager.LoadSceneAsync() を使用した非同期読み込みを採用しています。
通常の方法（LoadScene）だと読み込み中にゲーム画面が完全にフリーズしてしまいますが、非同期読み込みにすることで、ローディング中もアニメーションを動かしたり、進捗（％）を計算して表示したりすることができます。

3. コルーチンによる画面遷移の流れ

実際のロード処理は LoadSceneAsyncCoroutine というコルーチン（一定時間ごとに処理を小分けにして実行する仕組み）で以下の順番で実行されます。

  • フェードイン:
    • fadeDuration（設定値、デフォルト0.5秒）かけて、ロード画面の透明度を0から1へアニメーションさせて表示します。
    • 同時に、設定されたTips画像リストからランダムで1枚を選んで表示します。
  • 読み込みループと進捗表示:
    • while (!operation.isDone) で読み込みが終わるまでループします。
    • Unityの仕様上、読み込み進捗は「0.0 ～ 0.9」で完了となるため、これを progress / 0.9f と計算し直し、0%〜100%のパーセンテージテキストとしてUIに表示します。
  • 意図的な待機とシーンアクティブ化:
    • operation.allowSceneActivation = false にしておくことで、ロードが裏で完了しても勝手に次のシーンに切り替わらないように止めています。
    • ここで minLoadingTime（最低ローディング時間、デフォルト2秒）のタイマーをカウントしています。「ロードが一瞬で終わってしまい、Tipsが読めない」という事態を防ぐための工夫です。
    • ロードが完了（進捗0.9以上）し、かつ最低待機時間を過ぎた瞬間に operation.allowSceneActivation = true にし、次のシーンへ遷移させます。
  • フェードアウト:
    • シーン遷移完了後、再度 fadeDuration かけて画面を透明にしていき、ロード画面を隠します。

4. Tips（ヒント画像）表示のオンオフ機能

LoadScene(string sceneName, bool showTips = true) メソッドは、第2引数でTipsの表示/非表示を切り替えられるようになっています。
showTips を false にして呼ぶと、Tips画像や%表示が出なくなり、さらに minLoadingTime の待機もスキップされるため、「単に画面を暗転させてサクッとシーン遷移したい場合」にも使い回せる設計になっています。

5. ボタンからの呼び出し

ボタン等から呼び出す側（例：change_scene_button.cs）では、以下のようにマネージャーの存在を確認して呼び出しています。

if (LoadingScreenManager.Instance != null) {
    LoadingScreenManager.Instance.LoadScene("Main");
} else {
    SceneManager.LoadScene("Main"); // フォールバック
}

万が一ロード画面のマネージャーが配置されていないシーンでテストプレイをした場合でも、エラーにならず通常のロード処理が走るように安全対策（フォールバック）がされています。

まとめ：
「シングルトンでUIを維持し、コルーチンを使って非同期で裏側でシーンを読み込みながら、その進捗を計算して%表示しつつ、指定秒数は必ず待機してTipsを読ませる」という仕組みで作られています。
